\begin{abstract}
This laboratory implements UART, I2C, and SPI communication together with pulse-width modulation. A UART-driven calculator receives three two-digit integers and reports either their sum or product. The STM32 then operates as an I2C master to control an Arduino LED interval and read either a two-byte analog sample or a four-byte character sequence. The same analog sample is acquired through SPI and mapped first to an LED duty cycle and then to a servo command pulse. The four tasks combine interrupt-driven terminal input, structured peripheral transactions, byte reconstruction, and timer compare control in one modular application.
\end{abstract}

\section{Introduction}

Embedded systems commonly combine several communication interfaces because each protocol serves a different purpose. UART provides a direct text interface, I2C connects addressed devices on a two-wire bus, and SPI offers synchronous full-duplex transfers controlled by chip select. PWM converts numerical control values into timed output waveforms suitable for LED brightness and servo position control.

The application is organised as a UART menu with a state machine. Received characters are assembled into complete lines by the USART2 interrupt callback, while the main loop parses commands and executes the selected task. I2C1 and SPI1 communicate with the supplied Arduino slave programs. TIM2 and TIM21 generate the two PWM outputs.

\section{Task 1: UART Calculator}

USART2 is configured for asynchronous communication at 115200 bit/s with eight data bits, no parity, and one stop bit. Reception is interrupt driven one byte at a time. When a carriage return or line feed is received, the completed line is processed by the application state machine.

\section{Task 2: I2C Command and Data Selection}

The STM32 is the I2C1 master and the Arduino is the slave at seven-bit address \texttt{0x55}. The first UART selection is converted to one of the commands \texttt{0x80}--\texttt{0x83}, which selects the Arduino LED interval. The second selection chooses register \texttt{0x00} or \texttt{0x01}.

Register \texttt{0x00} returns a two-byte analog sample in little-endian order. If the received bytes are $b_0$ and $b_1$, the value is reconstructed as

\[
A=b_0+(b_1\ll 8).
\]

Register \texttt{0x01} returns the four ASCII bytes \texttt{RTCA}. Listing~\ref{lst:task2} implements the command write, register selection, read transaction, and data reconstruction.

\section{Task 3: SPI Analog Input to LED PWM}

SPI1 operates as a mode-0, MSB-first master with a prescaler of 128. The \SI{32}{\mega\hertz} peripheral clock therefore produces

\[
f_{\mathrm{SCK}}=\frac{\SI{32}{\mega\hertz}}{128}=\SI{250}{\kilo\hertz}.
\]

The Arduino exposes the lower and upper ADC bytes through commands \texttt{0x00} and \texttt{0x01}. Each register read sends its command and then a dummy byte to generate the clocks for the reply. The two bytes are combined as a 16-bit value.

TIM2 generates the LED waveform. With \texttt{PSC = 31} and \texttt{ARR = 999},

\[
f_{\mathrm{PWM}}=
\frac{32\,000\,000}{(31+1)(999+1)}
=\SI{1}{\kilo\hertz}.
\]

For a 10-bit Arduino sample $A\in[0,1023]$, the compare value is

\[
CCR_{\mathrm{LED}}=\left\lfloor\frac{1000A}{1023}\right\rfloor,
\qquad
D=100\frac{CCR_{\mathrm{LED}}}{1000}\ \%.
\]

Thus $A=0$ produces 0\%, $A=512$ produces approximately 50\%, and $A=1023$ produces 100\% duty cycle. The SPI transaction and LED mapping are shown together in Listing~\ref{lst:task34}.

\section{Task 4: SPI Analog Input to Servo PWM}

TIM21 generates the servo control waveform. The same prescaler gives a \SI{1}{\mega\hertz} counter, so one timer count represents \SI{1}{\micro\second}. With \texttt{ARR = 19999}, the PWM period is

\[
T_{\mathrm{servo}}=\frac{(31+1)(19999+1)}{32\,000\,000}
=\SI{20}{\milli\second},
\qquad f_{\mathrm{servo}}=\SI{50}{\hertz}.
\]

The analog input is mapped linearly to a pulse width from \SI{1000}{\micro\second} to \SI{2000}{\micro\second}:

\[
CCR_{\mathrm{servo}}
=1000+\left\lfloor\frac{1000A}{1023}\right\rfloor.
\]

Under a nominal $0^\circ$--$180^\circ$ servo mapping, the corresponding command angle is

\[
\theta=\left\lfloor\frac{180A}{1023}\right\rfloor.
\]

The end points therefore command \SI{1000}{\micro\second} at $0^\circ$ and \SI{2000}{\micro\second} at $180^\circ$, while the midpoint is approximately \SI{1500}{\micro\second} at $90^\circ$.

\section{Conclusion}

The laboratory integrated three serial interfaces with two timer-controlled outputs. Interrupt-driven UART reception supported a menu-based calculator and parameter entry. I2C transactions selected the Arduino LED interval and retrieved either a reconstructed analog value or the four-byte text response. SPI register transactions acquired the same 10-bit sample as two bytes. Linear timer mappings then converted this sample into a \SI{1}{\kilo\hertz} LED duty cycle and a \SI{50}{\hertz} servo pulse. The modular implementation separates terminal control, protocol exchange, and PWM conversion while retaining a single application flow for all four tasks.
